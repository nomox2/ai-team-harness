# (가칭) 가계부 — 작업 흐름 (내 작업 스토리)

`story-service.md`는 "무엇을 위한 일인지"의 기준이고, 이 문서는 "내가 실제로 어떻게 하는지"다. 둘을 섞지 않는다.

## 작업 흐름 7문장

1. 나는 다른 가계부·금융 앱의 실제 화면(기록, 내역, 통계, 예산 화면)을 레퍼런스로 수집한다.
2. 나는 레퍼런스를 분석해서 우리 서비스에 반영할 점을 정리한다.
3. 나는 분석 내용과 PRD를 토대로 화면 5개(홈·기록하기·내역·통계·예산·설정)의 화면 설계 문서를 구체화한다.
4. 나는 바이브코딩으로 레퍼런스와 화면 설계를 반영한 UI 키스크린 2~3개를 390×844 HTML로 만든다.
5. 나는 내부 관계자들과 협의해서 컨셉 시안을 확정한다. ← 멈칫
6. 나는 확정된 시안을 기반으로 디자인 토큰과 컴포넌트를 정리하고, 나머지 화면을 바이브코딩으로 만든다.
7. 나는 완성된 화면에서 토큰·컴포넌트가 가이드를 어기지 않았는지, 모든 기록 항목에 금액·카테고리·날짜가 있는지, 홈에 이번 달 남은 예산이 있는지 검토한다. ← 멈칫

## 산출물 · 게이트 · 에이전트 경계

| 2 | 분석 정리 → `analysis.md` | | |
