# AI 팀 하네스

AI에게 "화면 하나 만들어 줘"라고만 하면 매번 결과가 달라지고, 결국 직접 고치게 됩니다.
이 하네스는 **기획서(PRD)를 읽고 리서치 → 설계 → 시안 → 승인 → 디자인 → 판정**을 정해진 순서와 기준으로 돌려서, 같은 기준으로 화면을 만들게 하는 Claude Code 작업 틀입니다.

예시 서비스는 가계부 앱입니다.

## 어떻게 돌아가나요

| 단계 | 담당 | 하는 일 |
|---|---|---|
| P1 리서치 | 모아 | 유아이볼에서 비슷한 앱의 실제 화면을 찾아 레퍼런스 정리 |
| P2 설계 | 하루 | 고른 화면에 들어갈 요소를 `screens.md`로 설계 |
| P3 컨셉 시안 | 소라 | 기준 화면 크기의 HTML 시안(키스크린) 제작 |
| 승인 | 대표(사람) | 시안을 보고 승인 또는 반려 |
| P4 디자인 | 코다 | 승인된 시안으로 토큰을 정리하고 화면 전체를 HTML로 제작 |
| P5 판정 | 테스 | 스크립트로 기준 통과 여부 판정 |

- 각 단계가 끝나면 **게이트**(`harness/scripts/verify.mjs`)가 통과 여부를 판정합니다. 에이전트의 의견은 판정이 아닙니다.
- 판정 숫자는 `harness/rules.yaml` 한 파일에만 있습니다.
- 사람이 하는 건 **시안 승인** 한 곳뿐입니다. 훅이 에이전트가 대신 승인하는 것을 막습니다.
- 실패하면 정해진 단계로 되돌아가고, 같은 게이트에서 여러 번 실패하면 멈추고 사람을 부릅니다.

## 준비물
- [Claude Code](https://claude.com/claude-code)
- Node.js (게이트 스크립트와 훅이 씁니다)
- 유아이볼 MCP 연결 (P1 리서치용)
- 기획서 `docs/prd.md` — 아래 5블록 형식

## 쓰는 법
1. 이 저장소를 받고 이 폴더에서 Claude Code를 엽니다.
2. `docs/prd.md`를 내 서비스로 채웁니다 (예시는 가계부 PRD).
3. Claude Code에서 `/run-harness 홈`처럼 화면 이름과 함께 실행하거나, "하네스 돌려줘"라고 말합니다.
4. 시안 단계에서 멈추면 시안(`runs/<실행 이름>/p3-concept/key-*.html`)을 보고 승인합니다.
   - 승인: `node harness/scripts/approve.mjs <실행 이름>`
   - 반려: `node harness/scripts/approve.mjs <실행 이름> --reject "사유"`
5. 끝나면 `runs/<실행 이름>/p4-design/screens/`에 화면 HTML이 생깁니다.

게이트나 규칙을 고친 뒤에는 `node harness/tests/run-tests.mjs`로 판정이 바뀌지 않았는지 확인합니다.

## PRD 5블록
하네스는 기획서를 이 다섯 칸으로 읽습니다. 3번이 가장 중요합니다.
1. 한 줄 정의
2. 주요 사용자 1명 (누구 / 지금 무엇에 지쳐 있나)
3. 사용자 시나리오 2~3개
4. 만들 화면 3~5개 (이름만)
5. 지켜야 할 것 / 안 할 것 — 완성된 화면을 보고 O/X로 판정할 수 있게 씁니다

## 앱마다 하네스 만들기
이 저장소의 `docs/`, `harness/rules.yaml`, `runs/`는 예시 서비스(가계부) 기준입니다. 새 서비스는 이 저장소를 템플릿으로 앱마다 폴더를 따로 만듭니다.

```
bash new-app.sh 내앱이름                       # 이 저장소 옆에 폴더를 만듦
bash new-app.sh 내앱이름 ~/Desktop/내앱         # 위치를 정해서 만듦
```
- 하네스 엔진(스크립트·훅·직원 설명서·스킬)은 그대로 가져가고, `docs/`와 `harness/rules.yaml`은 **빈 템플릿**으로 시작합니다. 가계부 내용과 실행 결과는 따라오지 않습니다.
- 만든 폴더의 `CLAUDE.md` 맨 아래 "새 앱 준비"를 순서대로 채웁니다 (PRD → 화면 이름 → 판정 조건 → 디자인 규칙).
- 규칙이 아직 비어 있는 항목(색·폰트·서비스 조건 등)은 판정이 건너뜁니다. 채운 항목만 판정합니다.
- 앱마다 폴더가 따로라 문서·규칙·실행 결과가 서로 섞이지 않습니다.

## 폴더
| 폴더·파일 | 내용 |
|---|---|
| `CLAUDE.md` | 하네스 규칙의 원본 |
| `docs/` | 기획서, 디자인 규칙, 판정 기준, 작업 흐름 |
| `harness/` | 게이트 스크립트, 판정 규칙(`rules.yaml`), 테스트 |
| `.claude/agents/` | 직원 5명(모아·하루·소라·코다·테스) 설명서 |
| `.claude/hooks/` | 에이전트가 쓸 수 없는 곳을 막는 훅 |
| `.claude/skills/run-harness/` | 실행 절차 |
| `runs/` | 실행 결과 예시 (홈·기록하기·내역·예산·설정, 화면 미정 탐색) |
| `template/` | 새 앱용 빈 템플릿 (`new-app.sh`가 가져감) |
| `new-app.sh` | 새 앱 하네스 폴더 만들기 |
| `하네스-만든-과정.md` | 이 하네스를 만든 과정 |
